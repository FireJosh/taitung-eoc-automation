# 05 · 人在迴路

> 本文件說明人工介入的機制設計：中斷與續跑、決策模型、修改入帳與權限邊界。

---

## 1. 核心原則：沒有「系統自動結案」的路徑

工作流的所有分支，最終都匯流到人工協調節點。
即使品質評分通過、即使沒有任何異常，報告仍然必須經人簽核才算完成。

```
評分通過  → A6 → 人工簽核
評分不足  → 退回重寫（最多 3 次）→ 仍不足 → A6 → 人工簽核
重大異常  → Hard Gate → 人工裁決 → 續跑或終止
格式失敗  → Hard Gate → 人工裁決
```

**這是刻意的架構限制，不是流程尚未自動化。**
災害處置報告是對外的正式文件，責任必須落在具名的人身上。

---

## 2. 中斷與續跑

### 2.1 中斷不是失敗

異常時系統不拋出例外，而是呼叫工作流框架的中斷機制，
將當前狀態連同異常清單交給外部，流程**就地凍結**。

差別很重要：
- **失敗**＝流程結束，需從頭重跑
- **中斷**＝流程暫停，可從原地繼續

災害現場的人工裁決可能需要數分鐘到數小時（例如要打電話向鄉鎮確認），
中間可能跨越系統重啟。中斷模型讓這件事變成常態而非例外。

### 2.2 裁決後的狀態處理

裁決為「核可續行」時，系統除了續跑，同時把所有異常標記為**已解決**
而非刪除。

> **異常被人看過的事實會留在紀錄裡。**
> 事後檢討時能回答的不只是「當時有沒有異常」，還有「當時的人怎麼判斷的」。

### 2.3 終端狀態保護

已進入完成或失敗狀態的執行緒，**拒絕再次續跑**。
續跑請求會被明確回絕，而不是靜默地跑出第二份報告。

這道護欄防的是重複簽核與重複產報——在多人輪班交接的環境下，
「上一班是不是已經送出了」是很常見的混淆。

## 3. 決策模型

| 決策 | 語意 | 後續 |
|---|---|---|
| `approved` | 採用草稿 | 產出最終報告 |
| `modified` | 修改後採用 | 以修改後內容產出，並記錄差異 |
| `rejected` | 退回 | 不產出，記錄退回理由 |

決策套用邏輯抽離為獨立的純函式模組，不與工作流節點耦合——
可單獨測試，也可在不啟動整個工作流的情況下驗證決策行為。

---

## 4. 修改入帳

承辦人的每一次修改，以差異（diff）形式寫入帳本：

| 欄位 | 內容 |
|---|---|
| 修改前內容 | 原始草稿片段 |
| 修改後內容 | 承辦人改寫後的片段 |
| 修改人 | 具名 |
| 時間 | 修改時刻 |
| 原因分類 | 語氣錯誤／事實不符／格式問題／政策調整 |
| 依據 | 修改所本 |
| 覆核 | 覆核狀態 |

### 4.1 寫入前先去識別化

差異內容在寫入帳本前先套用去識別化處理。
理由很直接：**帳本本身不能成為個資外洩的管道**。
災情內容可能包含民眾姓名、電話、地址，這些不該因為「留紀錄」而被複製到另一個資料表。

### 4.2 修改紀錄**不用於自動學習**

這是刻意的取捨，也是與許多「AI 自我改進」設計的分野。

帳本的用途是**稽核與統計**——人工修改率是系統可觀測指標之一，
修改原因分類可以看出系統在哪一類內容上最不可靠。

但它**不會回頭自動調整模型行為**。三個理由：

1. **錯誤案例會污染後續產出**。人工修改不必然是對的，
   把它當成訓練訊號等於把個案錯誤放大成系統性錯誤。
2. **行為會在無人察覺下漂移**。今天通過驗證的系統，
   三個月後可能已經是另一個系統，但沒有任何一次變更被審查過。
3. **無法回答「為什麼這次這樣寫」**。自動學習使系統行為失去可解釋性，
   這在需要對外負責的文件上是不可接受的。

規則的擴充走**人工審核的規則庫**路徑，不走自動學習路徑。

## 5. 權限邊界

| 角色 | 可建立工作階段 | 可啟動工作流 | 可提交決策 | 可管理使用者 |
|---|:---:|:---:|:---:|:---:|
| editor | ✅ | ✅ | ❌ | ❌ |
| reviewer | ✅ | — | ✅ | ❌ |
| admin | ✅ | — | ✅ | ✅ |

**關鍵是 editor 不能提交決策**：發動流程的人與核可的人分離，
這是最基本的內控原則，也直接對應「新進人員不會誤觸核准」的防呆需求。

---

## 6. 系統能力的邊界

| 系統做的 | 系統不做的 |
|---|---|
| 產出報告草稿並記錄產製過程 | 決定報告是否發布 |
| 標示異常與衝突並提供判斷依據 | 替人決定哪個數字對 |
| 保存修改與決策的完整軌跡 | 依據軌跡自動調整行為 |
| 提供儲存與送出功能 | **提供任何對外發送功能** |

介面上**沒有「對外發布」按鈕**。對外發布是系統外的既有行政流程
（陳核、用印、發文），系統不介入也無能力介入。

> **AI 接走的是重複勞力，責任與簽名留在人身上。**
